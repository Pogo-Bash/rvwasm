# Shared Qt (dylink.0 side modules) for the wasmdyn dynamic linker

Branch nqshared. Beside the static build, never in it: `$NQ/build-shared/qtbase`, `$NQ/sysroot-shared`
(`prep-sysroot.sh`), the static build's patched `$NQ/src` read-only, host tools `$NQ/host`.

    shared/prep-sysroot.sh        # once: sysroot-shared (static sysroot minus Qt/KF6/Plasma; dlfcn.h fix)
    shared/build-qt-shared.sh     # configure (once) + ninja Core + copy to sysroot-shared + check-dylib.py

- `bin/nqs-clang[++]`: nq-clang, except `-shared` links a side module: `wasm-ld -shared` + `dlcrt.o` + libunwind's
  Unwind-wasm.o + builtins; NO musl/libc++/libc++abi (the C library, ld-wasm, provides them: they stay imports);
  then `tablify.py --dynsym`. `dlcrt.S`, `tablify.py` are copies from branch wasmdyn (tests/wasmdyn).
- `check-dylib.py MODULE --provider ld-wasm`: dylink.0/tablify consistency and that every import has a provider.

Choices:
- Plugins are shared (`dlopen`ed from the plugin directory), not static plugins linked into WaylandClient: that is what
  Qt does when `BUILD_SHARED_LIBS=ON`, needs no change to Qt or the toolchain, and is the thing the dynamic linker is
  for. Static plugins would have needed the old `add_library` override and `Q_IMPORT_PLUGIN` glue back.
- Third-party code used by one library stays static inside it (FreeType, fontconfig, expat, libpng, libjpeg, harfbuzz,
  zlib in Gui; libdbus in DBus; OpenSSL in the tls plugin; PCRE2, double-conversion, zlib in Core). Two copies of zlib
  (Core's and Gui's, ~100 K) remain: stateless, left. `nqs-clang` now follows `usr/lib/nq-deps/NAME` as `nq-clang` does.
- Shared because it was duplicated: libwayland-client (each shell plugin and WlShellIntegration carried 600 K of it) and
  libxkbcommon (Gui, WaylandClient, the compose input context). `build-clib-shared.sh` links their static archives
  `--whole-archive` into `libwayland-client.so.0` / `libxkbcommon.so.0` (no rebuild), the `.a` leaves sysroot-shared.
  Left duplicated: the 22 `wl_*_interface` protocol data objects (generated by qtwaylandscanner into WaylandClient and
  WlShellIntegration as well as in libwayland-client); ELF-style first-definition-wins binds them to one.
- No OpenGL/EGL yet (`INPUT_opengl=no`): Mesa is static in the static build; a shared libEGL/libGLESv2 comes with Quick.
  No xcb, Sql, Testlib.
- NEEDED entries are file names (`libQt6Core.so.6.8.2`, `libxkbcommon.so`, `libwayland-client.so`): the rootfs needs
  those files (and the `.so` symlinks) in `/usr/lib`.
- Gap: a plugin `dlopen`ed after threads exist is compiled by each thread itself (runtime), fine for now.

## Result 2026-10-13: Konsole's shell: QProcess forked (`patches/nqshared-qtbase-vfork.diff`)

"Resource error (fork failure): Invalid argument" from Konsole's KPtyProcess: Qt 6.8's `QChildProcess::usingVfork()` is false whenever a
child modifier is set and `UseVFork` is not (`qprocess_unix.cpp`), and KPtyProcess/KPty always set one (setsid, TIOCSCTTY, dup2 of the pty);
`startChild()` then passes `FFD_USE_FORK` to `vforkfd()` and forkfd calls `fork()`, which is EINVAL without an MMU. Not the shell, not KPty.
The patch (on top of `nativeqt-qtbase.diff`, applied in place to `$NQ/src/qtbase`, so the static build has it too): on `__wasm__`
`usingVfork()` is always true, so the child runs by `vforkfd` -> `system_vforkfd` (clone with CLONE_VM|CLONE_VFORK|CLONE_PIDFD on a 128 KiB
stack; the modifier runs in it) as for every QProcess without a modifier. Rebuilt: `ninja Core` (24 s) and libQt6Core.so.6.8.2 (7,446,141 B)
installed into sysroot-shared.
